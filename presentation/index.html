01 — the problem

Every session ends. Everything the agent learned dies with it.

Context lives in the moment — and evaporates the second the window closes.

The knowledge existed. It was never captured where the next session — human or agent — could find it.

Plaintext by default

Every member, integration, and future export reads it — including the credentials.

Permanent by default

Nothing expires, nothing is revocable. A pasted private key is a pasted private key forever.

Unprovable by nature

Anyone can paste a "decision". Nobody can prove who actually made it.

Shared context should be readable by exactly the team — and signed by exactly its author. That is the bar Cogit is built to.

05 — how a commit moves

Build, seal, hash, sign, write — in that order.

01Build

The body — summary, details, tags — is wrapped in a versioned envelope with branch, parent, author, kind, and timestamp. envelope v1 · kind decision

02Encrypt

Sealed with XChaCha20-Poly1305 under the repo's 32-byte group key and a fresh 24-byte nonce. Only key holders can read it. xchacha20-poly1305

03Hash

sha256 over canonical JSON — sorted keys, no whitespace. Change one byte of ciphertext and the hash moves. sha256(canonicalJson)

04Sign

The wallet signs the commit hash; the signature travels inside the envelope and anyone can recover the signer. sig = signMessage(commitHash)

05Write

One Arkiv entity with public attributes and an expiry set by kind; the branch head is patched to the new hash. entity + attrs · head patch

06 — privacy architecture

The ledger carries proof. It never carries plaintext.

Public — anyone can read

  • repo & branch names
  • commit kinds & tags' existence
  • author wallet addresses
  • timestamps & expiry
  • hashes — for verification

Enough to query, verify, and expire the work. Nothing more.

Private — group-key holders only

  • summaries & detailed notes
  • tags & code snippets
  • credentials & connection strings
  • private keys shared as context
  • the group key itself

Sealed with XChaCha20-Poly1305 under the repo's 32-byte group key — fresh nonce per commit.

A verifier checks the hash and the signature — never the contents. Proof and privacy travel together.

07 — keys & identity

Two keys. Neither one ever travels.

Wallet key — proves you wrote it

Lives in .env on your machine. It signs the commit hash; verifiers recover your address from the signature alone. The key itself is in no envelope, no repo, no chat — it never needs to be pasted anywhere.

Group key — grants reading

32 random bytes generated at init. cogit invite shares it as cogit1:<repoId>:<key> — read access for exactly the people you add. Stored mode 600, gitignored.

The viewer — decrypts in the tab

The group key lives in browser memory only, per session. There is no backend to hold it — so there is no server that could leak it, and none that ever sees your plaintext.

Private keys pasted in chats are forever. Cogit removes the need: the key signs locally and never leaves the machine, while the context around it rides encrypted end-to-end.

08 — verification

Verify first. Decrypt only after.

Four ordered checks — first failure wins

BAD_HASHrecomputed hash ≠ envelope hash
BAD_SIGNATURErecovered address ≠ envelope author
OWNER_MISMATCHentity owner ≠ author — someone else's wallet wrote it
NOT_MEMBERauthor not in the repo member list
passes all four → decrypt, show, hand to agents
fails any → red badge, reason shown, never decrypted
verify — 4 checks

✓ hash 0x7c9e1f…a4d2 matches recomputation

✓ signature recovers 0x225f…6af7 = author

✓ owner 0x225f…6af7 = author

✓ member anurag ∈ [anurag, adarsh, ritesh, smriti, kushal]

× copy 0xd41b…f0c9 fails owner check — shown red, not decrypted

OWNER_MISMATCH is the check git cannot make: a copied commit re-posted by another wallet is rejected even with a valid signature.

Invalid entries never decrypt — junk cannot even try to reach Claude Code, Cursor, or opencode.

11 — privacy track

This is why it belongs in the privacy track.

End-to-end encryption

XChaCha20-Poly1305 with keys generated and held client-side. The chain only ever sees ciphertext.

seal before it leaves

Non-custodial by architecture

No backend exists. The CLI, MCP server, and viewer all talk to Arkiv directly — there is no server that could see plaintext.

there is no server

Pseudonymous identity

Authorship is a wallet address proven by signature — accountability without doxxing anyone on the team.

recover, don't reveal

Selective disclosure

Read access extends only by explicit invite; branch heads are single-writer by construction. Sharing stays deliberate.

invite = read only

Minimization over time

Per-kind expiry — 3 / 14 / 90 / 365 days — deletes what's no longer needed, enforced by the network, not a cron.

decay by design

Integrity before exposure

Unverified entries are never decrypted and never handed to an agent. Junk cannot even attempt to be read.

verify, then decrypt
